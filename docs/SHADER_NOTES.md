# 셰이더 참고 노트

## 0. 웹 버전의 '2D 같은' 툰 느낌은 어떻게 만들었나

웹 버전에는 별도로 짠 셰이더 파일이 없습니다. Three.js 기본 재질 두 가지와 코드로 그린 텍스처를 조합해 만화 같은 느낌을 냈습니다.

1. **`MeshToonMaterial` + 4단계 그라디언트 맵** (`cat3d.js` `toon()`)
   - 빛 방향과 면의 각도(N·L)로 밝기를 매끄럽게 바꾸는 대신, 폭 4픽셀짜리 텍스처 `[150, 200, 235, 255]`를 *Nearest* 필터로 읽어 **밝기를 4계단으로 끊습니다**.
   - 그래서 둥근 몸통에도 그라데이션 없이 셀 애니메이션처럼 면이 나뉘어 보입니다.
   - 가장 어두운 단계도 150/255(약 59%)라서 그림자가 진하지 않고 파스텔 톤이 유지됩니다.
2. **조명 3개** (`stage.js` `addLights`)
   - 반구광: 하늘 `#fff3e0`, 땅 `#d9b99b`, 1.05
   - 방향광: `#fff0d8` 1.6 (오른쪽 위 앞), `#ffd9c0` 0.5 (왼쪽 앞)
   - 모두 따뜻한 색이라 흰색도 크림색으로 보입니다.
3. **조명 없는 `MeshBasicMaterial`**: 잔디 바닥, 우리 마당, 눈·입, 장소 표시 링. 빛을 받지 않아 평면 일러스트처럼 보입니다.
4. **캔버스로 그린 텍스처**: 털 무늬, 흰 반점, 성격별 눈(8종), 입, 잔디 삼각형, 말풍선 라벨을 HTML 캔버스에 그려 붙였습니다. 굵은 외곽선과 큰 하이라이트가 손그림 느낌을 냅니다.
5. **외곽선은 꺼져 있음**: 뒤집힌 껍데기(inverted hull) 외곽선 코드가 있지만 `OUTLINES = false`라 쓰지 않습니다.
6. **안개(Fog)** `#d8f0f0` 45~95m: 먼 나무가 하늘색으로 흐려져 배경이 납작하게 보입니다.

### Godot에서의 재현 (`godot/shaders/toon*.gdshader`)

- 위 계산을 그대로 옮긴 `unshaded` 셰이더입니다. Godot 조명을 쓰지 않고, 반구광 1개와 방향광 2개를 전역 셰이더 uniform(`project.godot [shader_globals]`)으로 넣어 직접 계산합니다.
  - 계산식: `(반구광 + Σ 계단(N·L) × 빛색) × 알베도 / π`
- three r160과 같은 색 관리를 합니다. 색은 선형 공간에서 계산하고, 안개는 sRGB 변환 뒤에 섞습니다. Compatibility 렌더러는 출력이 sRGB(`OUTPUT_IS_SRGB`)라서 셰이더 안에서 직접 변환합니다.
- 결과를 웹 스크린샷과 픽셀 단위로 비교했습니다. 흙길 웹 (232,196,136) / Godot (231,196,136), 건물 벽 웹 (247,201,188) / Godot (250,201,185) 수준으로 맞습니다.
- 도형도 three의 Sphere·Capsule·Cylinder·Torus·Tube 생성 공식을 그대로 옮겼습니다(`three_geo.gd`). 그래서 텍스처가 웹과 같은 위치에 붙습니다.
- 팀원 .blend 고양이를 쓸 때도 이 셰이더(또는 같은 계단 조명을 가진 털색 셰이더)를 입히면 지금 화면과 같은 톤이 됩니다.

# 털 무늬 셰이더 (확정 아님)

셰이더 관련 구현을 할 때 참고할 내용입니다. 털 무늬 방식은 **아직 확정이 아니며**, 현재 코드(`godot/shaders/cat_coat.gdshader`, `godot/scripts/cat/cat_appearance.gd`)는 비교용 임시안입니다.

## 1. Blender 셰이더는 게임으로 그대로 넘어가나?

**아니요. Godot이든 웹(Three.js)이든 같습니다.** Blender 노드 셰이더는 Blender의 렌더러(EEVEE/Cycles) 안에서만 실행됩니다. 게임 엔진으로 넘어가는 통로는 사실상 **glTF(.glb)** 하나뿐이고, glTF는 "Principled BSDF + 이미지 텍스처" 형태의 표준 재질만 담을 수 있습니다.

| Blender에서 만든 것 | glTF → Godot / 웹(Three.js) |
|---|---|
| Principled BSDF의 Base Color, Metallic, Roughness, Normal, Emission, Alpha | ✅ 넘어감 |
| 위 값에 연결된 **이미지 텍스처** (UV, Mapping 노드의 이동·회전·크기) | ✅ 넘어감 |
| Clearcoat, Sheen, Transmission, Specular, IOR 등 | 🔸 glTF 확장으로 일부 넘어감 (엔진 지원 차이 있음) |
| Noise·Voronoi·Wave 등 **절차적 텍스처**, ColorRamp, 수학 노드 조합 | ❌ 사라짐 |
| Shader to RGB, 툰 셰이딩, 림라이트 같은 커스텀 조명 | ❌ 사라짐 |
| 드라이버, 지오메트리 노드로 만든 재질 효과 | ❌ 사라짐 |
| 버텍스 컬러 | ✅ 넘어감 (쓰려면 엔진 재질에서 켜야 함) |

- Godot이 `.blend`를 직접 import하는 기능도 **내부적으로 Blender를 실행해 glTF로 변환**하는 것이라 제약은 똑같습니다.
- 웹(Three.js)도 `GLTFLoader`로 같은 glTF를 읽으므로 같은 결과입니다. 절차적 셰이더를 웹에서 쓰려면 GLSL `ShaderMaterial`(또는 TSL)로 **직접 다시 작성**해야 합니다.
- 애드온의 **게임 규칙 검사**와 자동 변환기는 사라지는 노드를 경고로 알려 줍니다.

### 사라지는 효과를 살리는 방법

1. **Bake**: Cycles → Render Properties → Bake로 색(Diffuse Color)·노멀 등을 이미지로 구워서 Principled BSDF에 연결. 가장 확실하지만, 색이 텍스처에 고정됩니다.
2. **엔진 셰이더로 재작성**: 효과의 "규칙"을 Godot `.gdshader`(웹이면 GLSL)로 다시 구현하고, Blender에서는 그 셰이더가 쓸 **마스크·데이터 텍스처**만 만든다. 색이 유전자에 따라 바뀌어야 하는 털은 이 방식이 맞습니다.

## 2. 유전 털색에 왜 "마스크 + 게임 셰이더"를 추천하나

유전 가이드 기준으로 털은 기본색 4종(블랙·초콜릿·블루·라일락) × 흰 반점 유무 = 8종이고, 여기에 의상이 붙습니다. 앞으로 좌위가 늘면 조합은 곱으로 늘어납니다.

- **Bake 방식**: 조합마다 텍스처 한 벌 → 8종이면 8벌, 좌위가 늘수록 폭증. 모바일·웹 용량에 불리.
- **마스크 방식**: 팀원은 색과 무관한 데이터만 그림 → 게임이 유전자로 색을 계산해 칠함.
  - `white_mask`: 흰 반점 영역 (흰색 = 흰 털). S_일 때만 사용.
  - `detail_map`: 명암·털결 같은 회색조 디테일.
  - (나중에) 줄무늬·포인트 등 무늬 좌위가 생기면 마스크 채널을 추가 (R/G/B/A에 하나씩 넣으면 텍스처 1장으로 4종).

현재 임시 셰이더(`cat_coat.gdshader`)가 하는 일:
```
털색 = mix(유전 기본색, 흰색, bicolor ? white_mask : 0) × detail_map
조명 = 웹 버전 MeshToonMaterial과 비슷한 계단식 음영
```
유전 색표는 `cat_appearance.gd`의 `BASE_COLORS` 한 곳에 있습니다.

### Blender에서 같은 결과를 미리 보고 싶다면

Blender 머티리얼을 "마스크 → Mix Color(기본색, 흰색) → Base Color"로 만들면 Blender 화면에서는 비슷하게 보입니다. 이 Mix 노드 구성은 glTF로 그대로 넘어가지는 않지만, 마스크 **이미지**는 넘어가므로 게임 셰이더가 그것을 사용합니다. 정확한 연결 규칙은 셰이더 방식이 확정될 때 정합니다.

## 3. 리깅·Shape key·애니메이션 (셰이더 외 참고)

| 항목 | 넘어감 | 메모 |
|---|---|---|
| 아마추어 + 웨이트 | ✅ | Godot `Skeleton3D` |
| Action 키프레임 | ✅ | Action 하나 = 애니메이션 하나 (`idle`, `walk` …) |
| IK·컨스트레인트 | ❌ | Bake Action으로 키프레임화 |
| Shape key | ✅ | Godot Blend Shape. 체형 연속값(통통함·귀 크기 등)에 적합 |
| Shape key 드라이버 | ❌ | 게임 코드에서 값 설정 |
| 모디파이어 | 🔸 | Shape key가 없으면 적용된 상태로 내보냄. 있으면 적용 안 함 |
| 파티클 털(Hair) | ❌ | 게임에서는 쉘 텍스처·카드 방식으로 별도 구현 (웹 버전의 장모 솜털처럼) |

## 4. 렌더러 선택과 셰이더

웹과 모바일을 모두 고려해 Godot 프로젝트는 **Compatibility 렌더러(OpenGL ES 3 / WebGL2)** 로 시작했습니다.
- 커스텀 `.gdshader`는 Compatibility에서도 동작합니다. 다만 화면 공간 효과(SSAO, SSR, 볼류메트릭 안개 등)는 없습니다.
- PC 전용 고품질 버전을 따로 낼 경우 Forward+로 바꿀 수 있지만, 셰이더 코드는 대부분 그대로 씁니다.
